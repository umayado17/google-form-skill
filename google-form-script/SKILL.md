# Google フォームを作る・直す・書き出す（空のフォーム＋付属スクリプト1本方式）

このスキルは手順だけを書く。なぜこの方式にしたかは、リポジトリの README.md を参照する。

## 同梱物

| ファイル | 役割 |
|---|---|
| `scripts/form-tools.gs` | 利用者に渡すスクリプトの雛形。前半が共通部、後半が設定部（見本は授業アンケート） |

## スクリプトの形

利用者に渡すのは、いつも1本のファイル。

```
form-tools.gs
├─ 共通部  … 同梱物のまま。AIも書き換えない
│   ├─ onOpen（「フォーム道具」メニュー）
│   ├─ フォームを整える
│   │   ├─ 設定を点検する
│   │   ├─ フォーム設定を反映する
│   │   ├─ 無題の質問を消す
│   │   ├─ 指定された設問を消す
│   │   ├─ 指定された設問を直す
│   │   ├─ 今ある設問名を覚える
│   │   ├─ 設問を追記する
│   │   ├─ 指定された設問を動かす
│   │   └─ 追加の処理（設定部にある）
│   └─ フォームをJSON化
└─ 設定部  … AIがフォームごとに書く
    ├─ フォーム設定
    ├─ 設問定義
    ├─ 直す設問
    ├─ 消す設問
    └─ 追加の処理
```

「フォームを整える」の動き：設定部に書き間違いがあれば、フォームに触る前に止まる。題名が空の質問を消す（題名のない画像・セクションは残す）。「消す設問」に書いた設問を消す。「直す設問」に書いた設問の、書いた中身だけを変える。今ある設問名を覚え、「設問定義」のうち無いものだけを足す。「後ろに置く」の指定どおりに並べる。最後に「追加の処理」を通る。それ以外の今ある設問には触らない。二度実行しても二重にならない。

メニューから実行すると、終わったときに、したこと（消した・足した・動かした・知らせたいこと）が画面に出る。止まったときは理由が画面に出る。スクリプト エディタから実行したときは画面に出せないので、実行ログに出る。

設問名の比較は、前後の空白を無視する。

「フォームをJSON化」は、設定部と同じ形（フォーム設定・設問定義）に、書き出し専用の「参考情報」と「分岐」を加えて書き出す。

## 設定部の書き方

```
const フォーム設定 = { タイトル: '...', 説明: '...' };
const 設問定義 = [
  { 設問名: '...', 種類: '...', 必須: true, 後ろに置く: '...', ... },
];
const 直す設問 = [
  { 設問名: '今の設問名', 新しい設問名: '...', 選択肢: [...], 後ろに置く: '...' },
];
const 消す設問 = ['設問名', ...];
function 追加の処理(フォーム, 知らせる) {
}
```

| 種類 | 書ける中身（設問名・種類・説明・必須・後ろに置くのほかに） |
|---|---|
| 記述 | 入力チェック：'メール'・'URL'・'数字'・'なし' |
| 段落 | なし |
| ラジオ・チェック | 選択肢、その他（true／false） |
| プルダウン | 選択肢 |
| 目盛 | 下限（0か1）、上限（3〜10）、下限ラベル、上限ラベル |
| 日付・時刻 | なし |
| グリッド・チェックグリッド | 行、列 |
| 見出し・改ページ | 説明のみ（必須は無い） |
| ファイル・画像・動画 | スクリプトでは作れない（書き出しにだけ出る） |

「後ろに置く」には、目印にする設問名か `'先頭'` を書く。設問定義では、その設問を新しく足すときだけ効く。今ある設問を動かすときは「直す設問」に書く。

## 追加の処理

上の仕組みに無い依頼（フォームのURLを知らせる、編集者を足す、回答先スプレッドシートを作る、回答の受付を止める、分岐を付ける、確認メッセージを変える、など）は、設定部の `追加の処理` の中に AI が Apps Script で書く。何も無ければ空のまま渡す。

- 「フォームを整える」のたびに最後に通る。何度通っても結果が同じになる書き方にする（例：編集者を足すのは何度でも同じ。回答先を作るのは、すでにあれば作らない）
- 一回きりでよい処理は、次にスクリプトを渡すときに消す
- 利用者に見せたいことは `知らせる('...')` と書く。終わったときの画面に出る
- 利用者が頼んだことだけを書く
- 上の表や「直す設問」「消す設問」でできることを、追加の処理で書かない
- フォーム以外のサービス（メール送信、カレンダーなど）を使うと、許可画面がもう一度出る。そのことを利用者に伝える

## AIが守ること

- **単体スクリプトでフォームを生成しない。** `FormApp.create()` で一回こっきりの単体スクリプトを書かない。修正のたびに作り直しになるため。
- 共通部は、同梱の `scripts/form-tools.gs` から一字一句変えずに写す。AIが書くのは設定部だけ。
- 利用者には毎回、共通部と設定部を合わせた1本を丸ごと渡す。利用者の作業は「全部消して、丸ごと貼って、保存、メニューから実行」だけにする。ファイルを分けない、部分だけを渡さない。
- スクリプトを渡すたびに、次の案内を添える：「フォームの編集画面を開き直し、上部のパズルのピースのアイコン →『フォーム道具』→『フォームを整える』（書き出すときは『JSONに書き出す』）。終わると画面に結果が出るので、その表示を教えてください」
- 設定部には値と `追加の処理` の中身だけを書く。`追加の処理` の外に `FormApp` などの呼び出しを書かない。
- 設問名がその設問の目印。設問定義の中で設問名を重複させない。
- 消すのは、利用者が「消して」と指定した設問だけ。その設問名を「消す設問」に入れ、「設問定義」からは外す。消す前に、書き出しの参考情報の「回答数」を見る。回答があれば、消すと回答シートとのつながりが切れることを利用者に伝え、確認を取る。
- 直すときは「直す設問」に、直す中身だけを書く。同じ変更を「設問定義」にも反映する（名前を変えたら、設問定義の名前も新しい名前にする）。種類は直せない。種類を変えたいときは、利用者に確認して、消して足す。
- 一度直した・消した・動かした指定は、次に渡すときも残してよい（二度実行しても結果は同じ）。
- 関数名・変数名は日本語にする（同梱物にならう）。
- Zapier は使わない前提で進める（有料で全員は使えない）。

## 手順

### 1. 出発点を見分ける

| 出発点 | 進み方 |
|---|---|
| 何もない（なんとなく作りたい） | 手順2へ |
| 設計がすでにある（会話・文書・表で設問が決まっている） | 設計を設問の一覧に置き換え、手順2の確認から先へ |
| 前に作ったフォームがある（直したい・似たものを作りたい） | 「既存フォームを読む」を先に行い、書き出した設問定義を土台に手順2へ |
| フォームをAIに取り込みたいだけ | 「既存フォームを読む」だけを行う |
| 出口のスプレッドシートが先にある（逆向き） | 「逆向き」を先に行い、手順2へ |

### 2. 何を聞くかを洗い出す

次の3つのどれかで、設問の候補を一緒に作る。

- 利用者が頭の中にある項目を書き出して入力する → AI が整理する
- 利用者がやりたいことを言う → 「そのためにどんなデータが必要か」を AI と一緒に作る
- 前に作ったフォームを渡してもらい、「こんな感じのを作りたい」を改良する

設問の一覧（設問名・種類・必須か・選択肢）を利用者に見せて確認を取ってから次へ進む。

### 3. スクリプトを書く

同梱の共通部を写し、確認の取れた設問一覧を設定部に書いて、1本にして渡す。

### 4. 貼って実行してもらう

利用者に次をお願いする。

1. Google フォームで空のフォームを新しく作る（タイトルは何でもよい。設定部のタイトルに変わる）。既存のフォームを直すときは、そのフォームを開く
2. フォームの右上「︙」→「スクリプト エディタ」を開く。すでに別のコードが書かれていたら、消さずにその中身を AI に見せてもらう（回答の通知などが入っていることがある）。何も無いか、前にこのスクリプトを貼ったものだけなら、全部消して、渡された1本を丸ごと貼って保存する
3. 初回だけ、上の関数の選択欄で「フォームを整える」を選んで「実行」を押す。許可を求める画面が出たら次のように進んでもらう
   - 「権限を確認」→ 自分のアカウントを選ぶ
   - 「このアプリは Google で確認されていません」と出たら、「詳細」→「（スクリプト名）（安全ではないページ）に移動」→「許可」
   - 許可の一覧に「Google ドライブのすべてのファイルの参照、編集、作成、削除」と出る。書き出しのファイルを作るために使うだけで、自分で作ったスクリプトなので、進んでよいと伝える
   - 学校などの組織のアカウントで、許可の画面に進めない・止められる場合は、組織の管理者に確認してもらう（管理設定で止められているかどうかは、AIからは分からない）
4. 2回目からは、フォームの編集画面を開き直し、上部のパズルのピース（アドオン）アイコン →「フォーム道具」→「フォームを整える」で実行する（メニューはスプレッドシートのように上部のメニューバーには出ない。パズルのピースの中に、アドオンと並んで出る）
5. 終わると画面に結果が出る。その表示を AI に伝えてもらい、フォームを確かめてもらう。止まったときも、出た表示をそのまま伝えてもらう

### 5. 直すとき

1. 利用者に、パズルのピース →「フォーム道具」→「JSONに書き出す」を実行してもらう。画面に出たファイル名を教えてもらう
2. そのJSONを読む（Google Drive コネクタがあればファイル名で探して読む。なければ渡してもらう）
3. 利用者の「ここを直したい」「これを消して」「これを足して」「ここに入れて」を、設定部の「直す設問」「消す設問」「設問定義」「後ろに置く」に書き分ける。表に無いことは「追加の処理」に書く
4. 共通部と合わせた1本を渡し、手順4の2・4・5で実行してもらう

## 既存フォームを読む

Claude も ChatGPT も、フォームの中身を直接はあまり読めない。そこで JSON に書き出してもらう。

1. 同梱の `scripts/form-tools.gs` を、設定部を空にして渡す（フォーム設定は `{}`、設問定義・直す設問・消す設問は空、追加の処理は空）。空の設定部で「フォームを整える」を実行しても、題名が空の質問を消す以外は何も変わらない
2. 利用者に、そのフォームの「︙」→「スクリプト エディタ」で貼って保存してもらう（手順4の2と同じ注意）
3. 関数の選択欄で「フォームをJSON化」を選んで実行してもらう（初回は許可画面が出る。進め方は手順4の3と同じ）。2回目からはメニューの「JSONに書き出す」でよい
4. フォームと同じフォルダに「（フォームのファイル名）.json」ができる（毎回上書きされる）。そのファイル名を教えてもらって読む

書き出しの中身：

| 項目 | 中身 | 設定部に戻すか |
|---|---|---|
| 参考情報 | 回答用URL・編集用URL・回答数・回答の受付・回答先スプレッドシート・メール収集・回答の編集・1人1回・進行状況バー・設問の入れ替え・テストかどうか・確認メッセージ | 戻さない |
| フォーム設定 | タイトル・説明 | 戻す |
| 設問定義 | 設問ごとの中身。選択肢の分岐（`分岐`）と、セクションのあとの行き先（`このセクションのあと`）も出る | 戻す（分岐・このセクションのあと・ID は外す） |
| 書き出せない中身 | 入力チェック、ファイル設問の必須 | — |

書き出した設問定義を設定部に写せば、そのフォームを今後このスクリプトで直せる。写すのは、題名があり、設問名が重複しない設問だけにする。題名の無い画像・セクションや、同じ名前の設問は、設問定義から外しておけば触られずに残る。分岐を変えたいときは「追加の処理」に書く。

制限：読めるのは、利用者が編集権限を持っているフォームだけ。

## よくある依頼と書く場所

| 依頼 | 書く場所 |
|---|---|
| 選択肢を入れ替える（部屋一覧・クラス一覧が変わった） | 直す設問の選択肢 |
| 設問を途中に足す | 設問定義の後ろに置く |
| 設問の順番を変える | 直す設問の後ろに置く |
| 設問に英語などを併記する | 直す設問の新しい設問名・説明 |
| 同じ形のフォームをもう一つ作る | 同じ1本を、別の空のフォームに貼って実行 |
| 聞き方を点検してほしい | 書き出して読み、直す設問の案を出す |
| URLを知りたい・編集者を足したい・回答先を作りたい・回答を止めたい | 追加の処理（URLは書き出しの参考情報にもある） |

回答の集計・分析は、このスキルの外（回答シートを読む）。

## 仕組みでできないこと

- ファイルアップロード・画像・動画の設問は、スクリプトで作れない。利用者に手で足してもらう
- 入力チェックとファイル設問の必須は、書き出せない。設定部に書かれていなければ、今の状態のまま残る

## メニューについて

フォームでは `FormApp.getUi()` を使う（`SpreadsheetApp.getUi()` は動かない）。メニューは上部メニューバーではなく、パズルのピース（アドオン）アイコンの中に、インストール済みのアドオンと並んで出る。編集画面にだけ出て、回答者の画面には出ない。スクリプト エディタから実行したときは `getUi()` が使えないため、結果は画面ではなく実行ログに出る。

## 逆向き（出口のスプレッドシートが先にある）

前提：関連データが並んだスプレッドシートが先にある。

1. そのスプレッドシートを AI に読ませてもらう
2. 「このデータとこのデータを入力させるフォームを作りたい」と言ってもらう
3. 入力させる列を設問に置き換えた一覧を作り、手順2の確認から先へ進む

フォームを直接生成することはしない（Zapier が要るため）。必ず手順3〜4のワンクッションを通す。
